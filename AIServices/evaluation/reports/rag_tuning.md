## Outcome against the a-priori baseline (manual note)

The validation-selected configuration does **not** beat the deployed baseline on the
held-out test split. Baseline numbers come from
`evaluation/results/rag_baseline_20261119T060758Z.json` (chunk 1000 / overlap 200, k=5);
selected numbers are the table above (chunk 1000 / overlap 0, k=5):

| Metric (test, n=17) | Baseline 1000/200 | Selected 1000/0 |
|---|---|---|
| nDCG@5 | 0.0637 | 0.0131 |
| P@5 | 0.0588 | 0.0118 |
| R@5 | 0.098 | 0.0147 |
| MRR | 0.0824 | 0.0427 |
| hit rate@5 | 0.2941 | 0.0588 |
| nDCG@10 | 0.0937 | 0.0371 |

The validation gap that selected this configuration was 0.008 nDCG@10 (0.1844 vs 0.1764),
which is inside the noise of 42 single-annotator queries, and the test pass reverses it.
Direct inspection of best-gold-chunk ranks explains the drop: at 1000/200 five test queries
have a gold chunk in the top 5 (Q09 rank 5, Q20 3, Q28 5, Q59 5, Q60 5); at 1000/0 only Q59
stays inside (rank 4), while Q20 moves to 7, Q09 to 9, Q28 to 11 and Q60 to 14.
No code defect was found; chunking changed which passages surface first and the change was
unfavourable.

**Recommendation: keep the deployed chunking (1000 / 200) at k=5.** Chunk-size tuning is not
a promising lever for this corpus; the limiting factor is that gold passages sit at a median
retrieved rank of 14 because the query language is generic while the documents are dense
reference material.

## Limitations

- Ground truth is a single-annotator judgment set; no inter-annotator agreement exists.
- Unjudged passages are treated as irrelevant, which penalises a retriever that surfaces genuinely relevant passages outside the judged pool.
- Twelve chunk configurations were compared on 42 validation queries, so validation differences of a few points are within annotation noise; the test pass is the single confirmation.
- Ranking is exact cosine over production embeddings; Chroma's index is not exercised.
- Retrieval quality only; no answer faithfulness or citation correctness is measured.
